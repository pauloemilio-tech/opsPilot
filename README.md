# OpsPilot

**AI-powered operational intelligence for account management.**

OpsPilot is a business-oriented platform designed to consolidate operational data, identify accounts that require attention, and transform fragmented information into actionable insights.

The project is inspired by real-world enterprise challenges such as disconnected systems, manual analysis, inconsistent decision-making, and limited operational visibility.

Rather than treating AI as a standalone feature, OpsPilot is being designed around a simple principle:

> Technology should reduce operational complexity and help users make better decisions faster.

---

## The Challenge

Operational teams often rely on multiple systems to understand customer and account performance.

Relevant information may be distributed across:

* CRM platforms
* Order management systems
* Support systems
* Customer interaction records
* Revenue and performance data

This creates several problems:

* excessive time spent gathering information;
* inconsistent account evaluation;
* difficulty identifying high-risk accounts;
* limited visibility into growth opportunities;
* delayed decision-making.

OpsPilot aims to provide a unified operational view where data can be analyzed consistently and converted into clear priorities and recommendations.

---

## The Solution

OpsPilot centralizes account-related operational data into a single backend platform.

The system is being designed to support:

* unified account profiles;
* order and transaction visibility;
* support ticket tracking;
* customer interaction history;
* account health indicators;
* risk and growth scoring;
* operational dashboards;
* actionable recommendations;
* natural-language analysis powered by AI.

The MVP follows an incremental development approach, starting with a reliable data and API foundation before introducing analytics and AI capabilities.

---

## Running Locally

### Prerequisites

Make sure you have installed:

* Java 17+
* Docker
* Docker Compose
* Git

Maven does not need to be installed globally because the project includes the Maven Wrapper.

---

### 1. Clone the repository

```bash
git clone https://github.com/pauloemilio-tech/opsPilot.git
cd opsPilot
```

---

### 2. Start PostgreSQL

```bash
docker compose up -d
```

Check the container status:

```bash
docker compose ps
```

The PostgreSQL instance should report a healthy status before starting the application.

---

### 3. Run the backend

#### Windows

```bash
.\mvnw.cmd spring-boot:run
```

#### Linux / macOS

```bash
./mvnw spring-boot:run
```

The API runs by default at:

```text
http://localhost:8080
```

---

### 4. Check the API

```http
GET http://localhost:8080/api/health
```

Expected response:

```json
{
  "status": "UP",
  "service": "OpsPilot API"
}
```

## Database Management

Database schema changes are managed exclusively through **Flyway migrations**.

Hibernate schema generation is intentionally disabled.

```yaml
ddl-auto: validate
```

Migration files are stored in:

```text
src/main/resources/db/migration/
```

This ensures that database changes remain explicit, versioned, and reproducible.

## Development Principles

OpsPilot is intentionally being developed with a pragmatic approach.

The project prioritizes:

* business value over unnecessary technical complexity;
* clear and maintainable code;
* explicit business rules;
* reliable data before AI;
* incremental delivery;
* testable components;
* scalable architecture without premature optimization.

Technologies such as microservices, Kafka, Redis, and machine learning will only be introduced if the product requirements justify their use.

## Product Vision

The long-term goal of OpsPilot is to demonstrate how operational systems can move from fragmented data and manual analysis toward a unified decision-support platform.

Instead of simply displaying data, the platform aims to answer questions such as:

* Which accounts require attention today?
* Why is an account considered high risk?
* Which customers have high growth potential?
* What operational issues are affecting account performance?
* What action should an account manager take next?

The goal is to turn operational data into **decision-ready intelligence**.
